В данном проекте реализован минимальный REST API для работы с задачами (Todo): создание и получение всего списка. Данные хранятся в памяти процесса. Основной акцент сделан на расширенной настройке Swagger (OpenAPI) для документирования API.

---

## Шаг 1. Запуск и регистрация сервисов

При старте:

- подключаются контроллеры (`AddControllers`) — без представлений, потому что это чистое API;
    
- включается исследователь API-эндпоинтов (`AddEndpointsApiExplorer`) — нужно, чтобы Swagger мог собрать метаданные о маршрутах;
    
- включается генератор Swagger (`AddSwaggerGen`) — документирует API.
    

В отличие от учебного примера с `ProductService`, здесь нет отдельного сервиса, так как логика хранения задач тривиальна (статический список прямо в контроллере).

Дальше настраивается конвейер:

- в режиме разработки включаются Swagger и Swagger UI;
    
- HTTPS-редирект;
    
- маршрутизация контроллеров (`MapControllers`).
    

Обратите внимание: нет `UseRouting`/`UseEndpoints` в явном виде — `MapControllers` в минимальной модели сам подключает нужные этапы. Нет и аутентификации/авторизации — API открыт.

---

## Шаг 2. Модель

**Доменная модель `TodoItem`** — то, что хранится и возвращается клиенту: `Id`, `Title`, `IsCompleted`.

В этом простом проекте DTO не используется, так как клиент присылает ровно те же поля, что хранятся в модели (кроме `Id`, который присваивается на сервере). В реальном проекте для отделения контракта от внутренней модели лучше создавать отдельный `CreateTodoDto`.

---

## Шаг 3. Контроллер и работа с памятью

`TodoController` — тонкая обёртка над статическим списком задач. Список инициализирован одной задачей для демонстрации.

- `GetAll` (`GET /api/todo`) — возвращает список задач в формате JSON со статусом `200 OK`. Если список пуст, вернётся пустой массив `[]`.
    
- `Create` (`POST /api/todo`) — принимает задачу в теле запроса, присваивает ей новый `Id`, добавляет в список и возвращает `201 Created` с заголовком `Location`, указывающим на метод получения списка (так как отдельного метода получения по id нет).
    

Важная деталь: список задач статический, поэтому при перезапуске приложения все созданные задачи теряются. Кроме того, список не потокобезопасный (при одновременных запросах возможны гонки).

## Шаг 4. Настройка Swagger (OpenAPI)

_Это ключевая часть домашнего задания._

Вместо стандартного вызова `AddSwaggerGen()` без параметров, в `Program.cs` используется лямбда-выражение для настройки метаданных документа:

csharp

builder.Services.AddSwaggerGen(c =>
{
    c.SwaggerDoc("v1", new OpenApiInfo
    {
        Title = "Todo Management API",
        Version = "v1",
        Description = "API для управления задачами. Поддерживает фильтрацию и создание.",
        Contact = new OpenApiContact
        {
            Name = "API Support",
            Email = "support@example.com"
        },
        License = new OpenApiLicense
        {
            Name = "MIT",
            Url = new Uri("https://opensource.org/licenses/MIT")
        }
    });
});

Что даёт эта настройка:

- **Title** — красивый заголовок страницы Swagger UI (вместо стандартного "Swagger UI");
    
- **Version** — версия API, отображается в интерфейсе;
    
- **Description** — текстовое описание, которое видит разработчик при открытии документации;
    
- **Contact** — контактные данные команды (отображаются в разделе с информацией);
    
- **License** — условия использования API.
    

Благодаря этому Swagger UI превращается из простого списка эндпоинтов в полноценную документацию, по которой сторонний разработчик сразу понимает, что делает API и к кому обращаться.

## Шаг 5. Swagger

В режиме разработки доступны:

- `/swagger/v1/swagger.json` — описание API в формате OpenAPI (содержит все настроенные метаданные);
    
- `/swagger` — интерактивная страница Swagger UI, где можно посмотреть эндпоинты и отправить тестовые запросы.
    

Swagger собирает метаданные из атрибутов контроллера (`[ApiController]`, `[Route]`, `[HttpPost]`, `[HttpGet]`) и из модели. Вне режима разработки Swagger не подключается — это стандартная практика, чтобы не раскрывать описание API в продакшене.
